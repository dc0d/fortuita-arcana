# Issue template

Write the GitHub issue title as a specific outcome, not a vague activity. Do not repeat it in the body.

```markdown
## Problem

<What happens today, who it affects, and why it matters. Include evidence or reproduction steps where relevant.>

## Desired outcome

<What must become possible. For an investigation, what must become known or decided.>

## Acceptance criteria

- [ ] <Observable behavior with specific inputs and expected results>
- [ ] <Relevant error or edge-case behavior>
- [ ] <Existing behavior that must remain unchanged>

## Out of scope (optional)

- <Something a reader could plausibly assume is included but is not. Link a follow-up issue if one exists.>

## Constraints (optional)

<Required compatibility, performance, security, or operational limits, with verifiable conditions and thresholds where applicable>

## Context (optional)

<Relevant files, documentation, examples, and related issues>

## Open questions (optional)

- Blocking: <Decision required before the affected implementation begins>
- Non-blocking: <Question that can remain open without changing the agreed scope or acceptance criteria>
```

Problem, desired outcome, and acceptance criteria are the core sections. The remaining sections are optional.
